Compute, the workspace host

A workspace that lives in Dev

Compute describes its workspaces in one line: "Cloud workspaces bound to Dev. They run beside nsx-dev-use1 and see Dev services, flags and secrets." Here is what that means for Venkatesh's workspace, ws-vt-01.

1 · New workspace, step 4 of 4

Created from Bitbucket, inside Dev's network

The wizard takes commerce/order-service from Bitbucket Data Center. The region, us-east-1 private VPC, is locked and marked "set by Dev". ws-vt-01 is the Large size, 8 vCPU and 16 GB, which the wizard lists at $0.48 an hour, and it binds to nsx-dev-use1 / commerce with read and write.

2 · Bindings in Bridge

Five bindings, the same for every workspace

A Dev workspace connects to the cluster with read and write, to Kafka msk-dev-use1 to read, to the launchdarkly:dev flags, and to vault:secret/dev/commerce through workload identity with no static secrets. Models come from Bedrock in us-east-1 on Dev's quota.

3 · Sleep, expiry and spend

Idle workspaces go to sleep

A running workspace sleeps after 60 minutes idle and wakes from Compute. The wizard also offers an ephemeral switch that deletes the workspace when its branch merges. Venkatesh has 4 of the 6 workspaces he is allowed, and Compute shows $3.84 spent today. The design's prices are illustrative.

4 · Main against Dev

The one value that differs

Compute compares the configuration in main with what runs in the commerce namespace. Four of five keys agree. LOYALTY_TOPIC is order.confirmed.v2 in main and order.confirmed.v1 in Dev, from configmap loyalty-cfg, and that retired topic is why loyalty-consumer is crash-looping. R-2207 redeploys 1.9.0.

5 · CodeX terminals

Every terminal says where it runs

The v2 screens gave CodeX a terminal per environment. In v3 both terminals are Dev's. The workspace shell runs mvn -q verify with 43 tests and "Same result as Jenkins #419". The kubectl tab, labelled nsx-dev-use1 / commerce with read and write, shows the two crash-looping pods and the log line naming the v1 topic.

How the prototype does it

Workbench, the stand-in for CodeX

Atlas has no cloud workspace. Its Workbench screen plays the part of CodeX with fixed Commerce files, a prepared change and checks that look for strings. Knowing exactly what it does keeps a demo honest.

The repository header always shows commerce/order-service, branch feature/fraud-review and snapshot 8a7f1c2. The editor is a textarea, and only OrderService.java can be edited. A renderer numbers the lines, colours comments, strings, some Java keywords and annotations with regular expressions, and highlights any line containing fraudRisk. It is not Monaco, a Java parser or a language server (handbook 4.3).

Apply proposed change replaces the marker comment // Risk assessment belongs before payment authorization. with the prepared lines. It sets applied, clears tested and the evaluations, and adds an audit entry. Editing the source by hand also clears tested and changes the configuration fingerprint (4.3, 4.5).

Run checks sets tested from the predicate on the right and prints 3 / 3 local scenario checks passed. The terminal's three lines describe assessment before payment, review handling and event compatibility, which is more than the predicate tests (4.6).

Onboarding checks only that the repository identifier matches ^[\w.-]+/[\w.-]+$, so commerce/order-service passes and a full HTTPS URL fails. It saves provider, repository, region and tier as metadata, and Workbench keeps showing the Commerce fixture (4.2).

What it does not prove
  • The check never looks at call order or control flow, so it cannot show that the assessment runs before payment.
  • Nothing compiles the Java. The insertion has no fraudRisk field, client or timeout handler.
  • Nothing validates the event against the order.confirmed.v2 schema.
  • No model answers. The assistant waits 550 ms and returns prepared text.

Atlas prototype today

Workbench shows fixed Commerce files in a textarea editor. Apply is a string replacement, Run checks tests four terms, and the assistant picks one of five prepared answers by substring after 550 ms. Onboarding saves metadata only. There is no workspace, terminal, Git operation or pull request.

v3 design
  • CodeX: ws-vt-01 bound to nsx-dev-use1 / commerce, terminals labelled with their environment, an assistant that cites
  • Compute: 4 of 6 workspaces, five bindings, sleep and ephemeral rules, main against Dev
  • Reviews: PR #214 with @B's review from Matrix, contracts and build #418, and the merge rule
Production proposal

Reuse a mature, supported editor and extension environment with language and debug protocols, Git, terminals and isolated remote workspaces. Workers hold short-lived, narrow grants instead of ambient administrative credentials (handbook 14.8).

Other ways to do it

Cloud workspaces and AI code review both exist as products today. Vector's design ties the two to one environment and one graph, which is also the part it would have to build.
