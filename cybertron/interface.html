15 Design and road · the shell

One shell on every screen

Vector is drawn as a light, Apple-like Windows desktop app. All 28 screens sit in the same frame: a title bar that searches or asks @B, two global pickers, an environment strip and a sidebar in six plain groups.

How the look was chosen

Two rejections, then one shell

The look came out of a short run of attempts. Two dark ones were turned down, a light screen set followed, and version three put every screen in the same frame. The homepage is still open.

Earlier attempt · rejected

A dark concept poster

An early attempt was a dark concept poster, and the user rejected it. The direction he set for Vector is a Windows desktop application UI, so the screens had to look like a working application on a Windows machine.

Earlier attempt · rejected

Dark Windows windows

The next attempt drew real Windows windows, still dark, and that was rejected too. The user wants the UI light, clean and Apple-like, dislikes black backgrounds and weird colours, and wants detailed components kept clean and minimal.

13 October · v2

The first light set: 28 windows

Vector UI Concepts v2 drew 28 Windows-app windows at 1600 × 1000 in six rows, with sidebar links that turn the canvas into a clickable prototype. It fixed the palette used since: #FBFBFD and #F2F2F5 grounds, white cards with a 14 px radius, a #0071E3 accent. Shells still varied, with a full sidebar on dashboards and an icon rail on dense screens, and some screens picked their own environment.

13 October · v3

One shell, scoped to Dev

The same day, v3 rebuilt every screen on one identical shell scoped to Dev and added two boards, the open environment picker and the environment flow. That makes 30 boards: 28 screens and 2 diagrams. It follows the user's rule of one global environment dropdown at the top right of the title bar.

16 October · homepage directions

Six homepages, none chosen

Six full-fidelity homepage options, A to F, each set in its own typeface. They were built to choose a direction before the rest of the suite is redesigned, and nothing beyond the homepage is built until one is approved. None has been approved yet.

In the design

Reading one window

Home carries every part of the shell. Its cards show the design's other idea, work fused across tools, with each tool named in grey. Homepage direction C shows where the Oct 16 exploration took the same parts. Select a plate to open the full screen.

Plate 15.1 · v3 Home, Tuesday 13 October

The shell, part by part

  1. App and screen. The Vector mark, then the screen's name in grey: Home, Threads, Pipelines.
  2. Search or ask @B. One 480 px field between the app name and the pickers, Ctrl K. Each screen sets its own hint, such as "Search builds, jobs, logs — or ask @B" on Pipelines.
  3. Application picker. Commerce Orders, the application this window works on, chosen once for every screen.
  4. Environment picker. "Dev us-east-1", tinted blue, the only environment control in the app (chapter 04).
  5. Avatar and caption buttons. VT, then minimise, maximise and close, 46 px each, as on any Windows app.
  6. Environment strip. 28 px of pale blue that spells out what Dev resolves to and what you may do there.
  7. Six groups. Work, Run and ship, Observe and govern, Know, AI engineering, Connect: 27 links, the same on all 28 screens.
  8. Grey hints. The tool behind a screen (Jira, EKS, Jenkins) or a count (2 reviews, 1 approval, 960 repositories, 66 integrations).
  9. Ask @B. The yellow mark at the foot of the sidebar, also on Ctrl B.
  10. Since this morning. A purple-tinted panel where @B sums up Jira, Bitbucket, Jenkins, EKS, Confluence and Teams in three findings.
  11. Work fused across tools. Every card names its source: Jira, Teams calendar, Workspaces from CodeX, Jenkins commerce/dev, Bitbucket, the nsx-dev-use1 cluster.
Plate 15.2 · homepage direction C · Friday 16 October

One inbox for all work

  1. Queues. My work 3, Reviews 2, Approvals, Incidents 1, Agent runs 4 sit where v3 listed screens.
  2. Spaces and saved views. Ship, Observe, Know, CodeX, AI Studio, Govern, then saved filters such as Release 2.14.0.
  3. Ask @B, Ctrl B. Kept from v3, in the same place.
  4. Needs you. Three threads from three tools ranked first: build #418 with a fix ready, the CrashLoopBackOff on Stage, Priya Raman's review request.
  5. Today. The Teams calendar folded into the foot of the list, with Join on the 11:00 review.
  6. Six-stage lifecycle. Understand, Develop, Experiment, Evaluate, Govern, Ship, each with its tool and state. Develop is red for #418.
  7. @B next best step. One recommended action, its reason, and Approve and push, Review the diff, Why this step?
  8. Timeline "from 6 tools". Ratchet, Jenkins, Confluence, Bitbucket, Evals, Teams and AllSpark events in one column.
  9. Linked, 7 objects. PR, workspace, prompt, ADR, build, impact and release, one click each.
  10. Stage us-east-1. The homepage set is scoped to Stage; the picker keeps its place top right.

How the prototype does it

The prototype looks different

Atlas, the working React prototype, has its own styling: tokens from enterprise.css laid over Tailwind and shadcn defaults. It looks related to the v3 boards, with different values almost everywhere. Handbook sections 3.1, 12.2 and 12.5 give them.

Two details matter if the prototype is restyled to match. Ctrl B means different things in the two layers. Atlas also styles some components twice, in globals.css and again in enterprise.css, so the handbook warns that the first rule found for a class may not be the one that renders (12.1).
