How the prototype does it

One string decides what counts

Atlas, the working prototype, applies the same rule in the browser. Every run and evaluation keeps the configuration string it was produced under, and a gate counts evidence only when that string equals the current one.

configKey is JSON.stringify of an ordered array of 13 values. Change any of them, even a space in the prompt, and the string changes. Each run, the latest evaluation and the staged release store the string they saw.

Some things are left out: the prompt version number, the model's endpoint and approval metadata, the budget amount, onboarding metadata, connector settings, dataset preview selection and tool sandbox input. Two prompts with identical text but different version numbers produce the same key.

A configuration change never deletes old evidence. It stops counting. Return to exactly the same values and the old run and evaluation count again, but the staging status and approvals do not come back.

The Safety guard and the six policy switches are separate. Guard off fails three evaluation cases (T03, T04, T08). Turning off a required policy can leave evaluations at 8 of 8 and still block release. The budget policy changes the fingerprint but is not a gate.

  • Not a digestThe key is a plain string compared for equality. Whitespace changes it, a version number does not, and nothing is signed or content-addressed.
  • Persona approvalsChoosing Commerce owner or Application Security writes Approved or Changes requested; choosing again replaces it. No identity, timestamp or signature is stored, and Changes requested does not send the release back to Draft.
  • No Deployed stateTwo approvals deploy nothing. The release stays at Approval requested, and there is no deployment button, rejection or rollback state.
  • A manifest made on screenThe release manifest is assembled at render time from current state and fixed text. Its rollback target v0.3.2 is illustrative.
  • No clockEvidence does not expire by time, and the audit is a list of browser strings the user can clear.

Atlas prototype today

Four gates computed in the browser from configKey, a 13-field JSON string. States Draft → Staging → Approval requested; a fingerprinted change returns the release to Draft and clears approvals. Approvals are persona strings with no identity, timestamp or signature, and nothing deploys.

v3 design
  • GroundBridge release page: lifecycle, four gates, bundle card with fingerprint cfg-7f3a9c
  • Approvals bound to bundle, source namespace and configuration; permissions checked again at signing
  • Vault: immutable artifacts with lineage, bundle signed by GroundBridge
  • Handoff through Jenkins commerce/qa, then verify and reconcile
Production proposal

A release pins source or image, prompt digest, model deployment, agent plan, tool contracts, dataset and evaluator versions, retrieval recipe, knowledge-snapshot policy, evaluations and approval receipts, and freshness compares immutable digests. Approvals sit in a transactional store, bound to the exact proposal, environment, policy version and expiry. The approved deployment system still delivers; the platform requests it and reconciles what it observes (handbook 14.6, 14.7, 14.10).
