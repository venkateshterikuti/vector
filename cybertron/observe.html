Each night

Estimates meet the bill

How the prototype does it

One number drawn as six spans

Atlas has a Traces & usage screen and a Cost intelligence screen. Neither reads telemetry. The waterfall is computed from one recorded latency per run, and the cost dashboard is a fixed table of its own.

Traces & usage · handbook 9.1–9.2

For a run with recorded latency L, the screen synthesizes six spans. Five are fixed and total 560 ms; the model span takes the rest, with a floor of 100 ms. Each bar is placed by dividing by L, and the ruler shows 0, L/2 and L.

Every current model descriptor has a latency of at least 780 ms, so the spans always add up to L. Risk Reasoner 3's descriptor is 1,840 ms, which gives the same 1,280 ms model span the v3 screen shows. Below 660 ms the floor would push the total past L and the bars past the ruler.

Every run appears as Completed, because the shared run function records only successful fixture runs. There is no OTel collector, trace backend, distributed correlation or provider measurement, and no connection to Optimus Logger.

operate.tsx · waterfall, as handbook 9.2 describes itrestated as code
// a run with recorded latency L (ms)
spans = [
  ["Authorize context",          60],  // RBAC + source permissions
  ["Retrieve enterprise graph",  140],  // 13 entities; citations
  ["Invoke fraud-risk-api",      220],  // synthetic result 0.91
  ["Model reasoning", max(100, L - 560)],
  ["Policy & schema validation", 90],  // from the captured guard
  ["Return decision",             50],  // structured response
]
left(i)  = sum(durations before i) / L
width(i) = duration(i) / L
ruler    = 0, L/2, L      // L < 660 → bars pass the ruler
Cost intelligence · handbook 9.3

Cost intelligence does not read the runs at all. It keeps fixed allocations by team, environment and application, with columns for inference, evaluation and infrastructure, a grouping selector and a period selector.

v3 design
  • Optimus Logger for order-service: KPIs, latency with deploy marks, a written explanation, logs with trace IDs, dependencies
  • Traces: six-span waterfall per AI run, tokens in and out, estimated cost, charged to Commerce Orders, linked to Evals on the same configuration
  • Cost (illustrative): team, application and resource views, Dev budget, savings from traces, nightly reconciliation with the cloud bill
Production proposal

A telemetry and cost plane with correlated spans, quality results, usage estimation, bill reconciliation and retention, which must tell operational success apart from answer quality (14.2). Trace, quality and cost analytics in a time-series or columnar store with attribution, retention and controlled content access (14.6). Provider billing stays authoritative for reconciled cost (14.10). Optimus Logger's API, schema, auth and trace identifiers are still open decisions (16.5).
