How the prototype does it

No pipeline screen yet

Atlas has no Jenkins, pipeline or cluster view, and the handbook lists Ratchet as a future capability with no dedicated screen or remediation engine (1.4). Three fixtures sit closest to this chapter.

Run checks in the Workbench is a string predicate. It passes when the prepared change is applied and the source mentions three names. The handbook says it "does not verify ordering, parse Java, inspect control flow, validate the schema, or test runtime behavior" (4.6).

Evaluation case T07 checks order.confirmed.v2 compatibility, and its actual value is always "backward compatible", so it always passes (7.1).

Together that means the riskDecision failure cannot happen in Atlas today. A source edit that put the field on the v2 event would still pass Run checks and T07. The v3 design's contract test is where the guide first shows the mistake caught.

The Incident triage assistant prompt template already states the manners Ratchet keeps in v3: read-only diagnostics first, approval for any remediation. Opening it shows a preview explaining that general inference is unimplemented (6, reference catalog).

Where riskDecision goes

Fixed. Eight services consume the published v2 schema. In JSON Schema, additionalProperties: false means "no additional properties will be allowed", so any property the schema does not list makes the event invalid.

The lab applies the real rule: it lists the payload's properties that OrderConfirmedV2 does not, and fails the stage if there are any. Stage names, log lines and Ratchet's words are the v3 design's; the passing lines are the CodeX terminal's. The design does not say what a v3 build would do, so the lab stops there.

Atlas prototype today

No Jenkins, pipeline or cluster views. Ratchet is a future capability with no screen or remediation engine (1.4). Run checks is a string predicate that does not validate the schema, and eval case T07 always passes. The Incident triage template opens only a preview.

v3 design
  • Pipelines: stage track, changes since last green, console, Ratchet Q&A with signals and confidence, proposed fix, re-run from a stage
  • Clusters: pod grid, CrashLoop row, version drift, Ratchet diagnosis, R-2207
  • Ratchet v5 (Wheeljack) in Agent studio; Sentinel: agents deploy to Dev only after a person approves each action
  • Roadmap Phase 2: "Approved write actions", including re-running stages
Production proposal

Tool contracts with typed input and output, risk class, scopes, allowed environments, timeout and retry eligibility. Idempotency keys and a side-effect ledger, so a write that timed out is reconciled before any retry. Approval bound to the exact proposal, environment, policy version and expiry (handbook 14.7).

Other ways to do it

Same failure, other tools

CI systems show stages and logs, and several now add an AI explanation of a failed job. Contract testing and Kubernetes troubleshooting each have their own established practice. Vector's design leans on all of them and adds the cross-system reading.
