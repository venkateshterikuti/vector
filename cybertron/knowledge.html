Knowledge · Ask your docs

An answer you can check

The v3 Knowledge screen answers one question from six pages. Five are cited by number, one is called out because it disagrees, and the screen says which documents have drifted away from the code.

1 · The question

Ask in plain words

The question is "How does order confirmation handle fraud review, and what changed today?" Knowledge searches five sources it keeps in sync: Confluence (4 spaces, 6,812 pages, synced 5 min ago), Bitbucket, Jira, opted-in Teams channels and Optimus Logger runbooks. Teams is paused.

2 · Only pages you can open

Six pages come back

Three Confluence pages, one Jira ticket and two Bitbucket files. The screen's first rule decides what may count: "Answers only use pages you can open." A page the asker cannot open never reaches the answer.

3 · Every claim is numbered

Five sources, one number each

Confirmation calls the Fraud Risk API after reserving stock and before authorizing payment [1][4]. Scores at or above 0.80 hold the order as pending_review and timeouts fail closed [2]. order.confirmed.v2 stays unchanged [5]. Each number opens its page. The answer took 2.4 s.

4 · Newer beats older

ADR-031 outranks a 214-day-old runbook

ADR-031 (Priya Raman, 2 h ago) sends any new event field to a v3 topic, so riskDecision stays internal [3]. The Order Service runbook still describes v1 and no fraud step. It is listed as the one source that disagrees and kept out of the answer. The Architecture board counts evidence freshness, the age of sources behind answers, as a measure of success.

5 · Drift is a finding

Draft an update

The runbook joins a "Drifted from code" list beside the Loyalty consumer setup (config key renamed, 61 days) and Payments retries (timeout 1000 → 1500 ms, 12 days). "Draft an update" starts the fix. The second rule: "Text inside documents is treated as content, never as instructions."

Retrieval lab · run 14

What the model would see

Any answer depends on the context a model is handed. The Retrieval lab lays that context out item by item, says what it excluded and why, and shows how a narrower scope quietly removes a fact the answer needed.

1 · Query settings

One query, explicit scope

The query is "Where should fraud assessment happen in order confirmation?" Scope is Commerce and Risk. Sources are Confluence pages, code and contracts and the Matrix graph, with Jira tickets off. Hybrid retrieval keeps 8 results, reranks them and respects source permissions.

2 · Run 14 · 412 ms

4 eligible, 2 excluded

Four items qualify, scored 0.92, 0.88, 0.81 and 0.74: the confirm() code path, the Fraud Risk API guide, the order.confirmed.v2 contract and a Matrix edge. Two are removed with a reason: the fraud model card because you do not have access to it, and the payments retries runbook because it is outside the selected scope.

3 · Scope changes the answer

Commerce only drops the contract

With Commerce only, three items come back instead of four. The contract sits in Risk scope, so it drops out, and a model would not know that new fields break order.confirmed.v2, which is exactly how build #418 failed. The lab's advice is to "keep Risk in scope for this task".

4 · Context budget

2,140 of 8,000 tokens

The model would get four short items, numbered [1] to [4], each with its kind: code, the RISK guide, the contract and the inferred Matrix edge. Together they use 2,140 of the 8,000 tokens available.

5 · Checks

One inferred fact, labelled

All four items are checked against your access and the freshest source was updated yesterday. One fact is inferred: the Order Service → Fraud Risk API edge, proposed in COM-2841 and "marked inferred until merged". The context can go to AllSpark or be saved as a recipe.

Production proposal · handbook 14.5 and 14.9

Permission is checked four times

"Answers only use pages you can open" is easy to draw and hard to build. The proposal checks access at four points along the path from a source system to an answer, and treats every document as data that cannot override policy.

How the prototype does it · handbook 5.8

Four documents and a substring

The Atlas prototype has a Retrieval lab too, with no search engine behind it. Its entire corpus is four fixture documents, each with a prepared score and a short list of keywords. Pressing Test retrieval runs a few lines of string matching.

The query is lowercased, split on non-word characters and stripped of tokens two characters or shorter. A document qualifies when one query token is a substring of one of its keywords, or a keyword is a substring of a token. Commerce only also removes any document whose kind is Contract. The sorted list is cut to the context limit of 2, 3 or 4, and a query that matches nothing gets an explicit no-evidence result.

The screen shows Lexical 30%, Semantic 40% and Structural 30% bars. They do not enter the calculation, and no embedding, semantic model, fusion service or retrieval API runs. Commerce only demonstrates scope filtering; it does not check who is asking.

Cited answers in the prototype live in the Workbench's Architecture Copilot, which routes a question to one of five prepared responses by ordered substring rules. Its citation chips open prepared evidence sheets whose line numbers are illustrative (handbook 4.4, 16.3).

  • The seeded fraud question matches all four documents with Commerce + Risk; Commerce only leaves three.
  • Changing strategy, scope, limit or rerank asks for another run; editing the query alone keeps the old results.
  • Open grounded experiment only navigates to Playground. Nothing carries the context across.

Production proposal

Source adapters feeding evidence and search, symbol, vector and graph projections with watermarks and replay (14.5). Access checked before retrieval, before a model, before cached results and before any side effect, with documents treated as data that cannot override policy (14.9).

Other ways to do it

Permission-trimmed answers with citations are now common in enterprise assistants. The tools differ in where they look, how much of the context they show you, and what they flag.
